# Online Banking System — Viva Preparation

## Project overview

**1. What is your project?**  
It is an Online Banking System prototype using Python Flask for the web application and MySQL for storing customer, login, account, beneficiary and transaction data. It simulates banking operations with fictional money.

**2. Why did you choose this project?**  
It demonstrates core DBMS concepts in a practical example: relational tables, keys, constraints, joins, normalization, views, and transactions.

**3. What is the role of Python?**  
Python runs the application logic, validates form inputs, checks login credentials, connects the website to MySQL and performs account operations.

**4. What is Flask?**  
Flask is a lightweight Python web framework. It maps URLs such as `/login` and `/transfer` to Python functions and returns HTML pages.

**5. What is the role of MySQL?**  
MySQL stores persistent records and enforces relationships and constraints. Data remains available when the web server restarts.

**6. Is this connected to a real bank?**  
No. It is a college demonstration only. Deposits, withdrawals and transfers move fictional demo balances inside the local database.

## DBMS concepts

**7. What is a DBMS?**  
A Database Management System is software used to create, store, retrieve, update and manage data in a controlled way.

**8. What is a primary key?**  
A primary key uniquely identifies each row and cannot be NULL. Example: `customer_id` in `customers`.

**9. What is a foreign key?**  
A foreign key references a key in another table and helps maintain referential integrity. Example: `accounts.customer_id` references `customers.customer_id`.

**10. What is a unique constraint?**  
It prevents duplicate values in a column or column combination. Here, usernames, emails and account numbers must be unique.

**11. What is normalization?**  
Normalization organizes data into related tables to reduce duplication and avoid insert, update and delete anomalies.

**12. Explain 1NF, 2NF and 3NF simply.**  
- **1NF:** each field contains one atomic value; there are no repeating groups.
- **2NF:** the table is in 1NF and every non-key attribute depends on the whole candidate key, not only part of a composite key.
- **3NF:** the table is in 2NF and non-key attributes do not depend transitively on another non-key attribute.

**13. Why are customers and accounts separate?**  
A customer can own multiple accounts. Keeping them separate avoids repeating customer details for every account and represents a one-to-many relationship.

**14. What is a JOIN?**  
A JOIN combines related rows from multiple tables using a matching condition. The project joins customers to accounts and transactions to source/destination accounts.

**15. What is a view?**  
A view is a stored query presented like a virtual table. `transaction_details` joins transaction rows with account numbers for reporting.

**16. What is an index?**  
An index helps MySQL locate rows faster for selected searches, though indexes require storage and can slow some writes. This schema indexes customer and transaction lookup columns.

**17. Why use `DECIMAL(14,2)` for money?**  
It represents fixed decimal values more appropriately for currency than binary floating-point types, which can have rounding representation issues.

**18. Why use InnoDB?**  
InnoDB supports transactions, row-level locking and foreign-key constraints, which are important for consistent account updates.

## SQL and security

**19. What is CRUD?**  
Create, Read, Update and Delete. In SQL these commonly correspond to `INSERT`, `SELECT`, `UPDATE` and `DELETE`.

**20. What is SQL injection and how does this project reduce it?**  
SQL injection is when untrusted input changes the meaning of an SQL statement. This project uses parameterized SQL placeholders (`%s`) instead of concatenating user input into queries.

**21. Are passwords stored as plain text?**  
No. The app stores a password hash generated by Werkzeug and verifies the entered password against that hash during login.

**22. What is a session?**  
A session stores small pieces of login state across requests. This project stores the logged-in user/customer IDs in Flask's signed session cookie.

**23. What is CSRF?**  
Cross-Site Request Forgery tricks a logged-in browser into submitting an unwanted request. The project's HTML POST forms use a session token checked by the server.

**24. Why is a foreign key not enough to validate a transfer?**  
A foreign key only ensures that the account exists. The application must also check that the source belongs to the logged-in customer, both accounts are active, the accounts are different, and enough balance is available.

## Transactions and banking logic

**25. What is a database transaction?**  
A transaction is a group of database operations treated as one unit. They are committed together or rolled back if an error occurs.

**26. Explain ACID.**  
- **Atomicity:** all steps happen or none do.
- **Consistency:** constraints and rules remain satisfied.
- **Isolation:** simultaneous operations should not interfere incorrectly.
- **Durability:** committed changes persist.

**27. Why must a transfer be atomic?**  
A transfer debits one account and credits another. If only the debit succeeds, money would appear to disappear. The app updates both balances and inserts the history row before one `COMMIT`.

**28. What does `ROLLBACK` do?**  
It undoes the changes made during the current uncommitted transaction.

**29. What does `COMMIT` do?**  
It permanently saves the changes in the current transaction.

**30. What does `SELECT ... FOR UPDATE` do?**  
It locks selected rows for the current transaction so another transaction cannot concurrently change the same locked rows until the first transaction finishes.

**31. How do you prevent a negative balance?**  
The Python logic checks the available balance while the account row is locked, the debit query also checks `balance >= amount`, and the schema has a `CHECK (balance >= 0)` constraint.

**32. What happens if a withdrawal exceeds the balance?**  
The app rolls back and displays an insufficient-balance message. It does not change the account balance or insert a successful withdrawal record.

**33. How does the app record deposits and withdrawals?**  
A deposit uses a NULL source account and a destination account. A withdrawal uses a source account and a NULL destination. A transfer stores both account IDs.

**34. Why do transfers have one row but affect two accounts?**  
One transaction row stores both `from_account_id` and `to_account_id`, while the two account balances are updated. This provides one shared reference code for the transfer.

## Important tables and columns

**35. What is stored in `customers`?**  
Customer profile details such as name, email, phone and address.

**36. What is stored in `users`?**  
The unique username and password hash linked to a customer.

**37. What is stored in `accounts`?**  
Account number, account owner, account type, balance, status and creation time.

**38. What is stored in `beneficiaries`?**  
The customer who saved a beneficiary, the beneficiary's account reference and a nickname.

**39. What is stored in `transactions`?**  
Transaction type, amount, source/destination account IDs, unique reference code, status, description and timestamp.

**40. What future improvements are possible?**  
OTP and email verification, an admin dashboard, account statements as PDF, password reset, stronger authentication, audit logging, rate limiting, HTTPS deployment, and integration with a regulated banking provider. Real-money use would require substantial security, compliance and professional review.

## Useful SQL examples to remember

```sql
-- Get account details with customer names
SELECT c.full_name, a.account_number, a.balance
FROM customers c
JOIN accounts a ON a.customer_id = c.customer_id;

-- Count transactions for each transaction type
SELECT transaction_type, COUNT(*)
FROM transactions
GROUP BY transaction_type;

-- Show each customer's total balance
SELECT c.full_name, SUM(a.balance) AS total_balance
FROM customers c
JOIN accounts a ON a.customer_id = c.customer_id
GROUP BY c.customer_id, c.full_name;
```
